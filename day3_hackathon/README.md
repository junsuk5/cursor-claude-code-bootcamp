## 📝 기획 (09:30–10:30) — PRD가 뭔가요?

**PRD(Product Requirements Document)** 는 "오늘 뭘 만들고, 뭘 안 만들지"를 한 장으로 정리한 문서입니다.
직접 쓰지 말고 **Claude와 대화하면서** 만드세요.

### 주제 정하기 — 뭐든 됩니다

| 분야 | 예시 |
| :--- | :--- |
| 🤖 자동화 | 반복하는 엑셀/문서 작업 스크립트, 매일 아침 정보 모아서 정리해주는 것 |
| 💼 업무 생산성 | 회의록 요약기, 사내 문서 검색, 일정 조율 도우미 |
| 🌐 웹 / 📱 앱 | Day 2에서 만든 것과 비슷한 형태의 작은 서비스 |
| 🎮 게임 | 브라우저에서 돌아가는 미니 게임 |

**"이거 만들면 회사에서 진짜 쓰겠다" 정도의 작은 아이디어가 가장 좋습니다.**
꼭 위 분류에 맞출 필요는 없습니다 — 평소에 손이 많이 가던 일이 있다면 그게 제일 좋은 소재입니다.

> [!TIP]
> **💡 도파민 포인트를 하나는 넣으세요.**
> 발표에서 옆 팀이 "어 저거 어떻게 한 거지?" 하게 만드는 건 대부분 기능 개수가 아니라
> **AI가 눈앞에서 뭔가를 대신 해주는 순간** 하나입니다. 그동안 실습에서 봤던 걸 떠올려보세요 —
> Playwright MCP가 스스로 브라우저를 조작하던 것, 대시보드가 텅 비었다가 채워지던 것처럼요.
>
> - 지저분한 데이터를 붙여넣으면 AI가 그 자리에서 정리해주기
> - 사진이나 화면을 넣으면 AI가 바로 분석·설명해주기
> - "이거 대신 해줘"라고 말하면 AI가 실제로 그 일을 처리하는 걸 보여주기
>
> 기능을 많이 넣기보다, **이 순간 하나를 잘 보여주는 데모**로 PRD를 짜보세요.

**[Claude Code 프롬프트]**
```text
하루 만에 2명이서 만들 수 있는 것을 기획하려고 해. 아이디어는 "<한 줄로 주제>"야.
(웹 서비스일 수도, 자동화 스크립트일 수도, 게임일 수도 있어 — 형태는 자유야.)

오늘 안에 못 끝낼 것 같은 기능은 과감히 빼고, 뺀 이유도 알려줘.
완성도보다 "오늘 안에 동작하는 것"을 우선해줘.

결과는 PRD.md 로 저장해줘. 포함할 내용:
1. 한 줄 소개 (누가, 무엇을, 왜)
2. 핵심 흐름 (사용자가 이걸로 뭘 하게 되는지, 화면이 있다면 화면 목록도)
3. 필요한 데이터나 외부 연동이 있다면 정리
4. 오늘 만들 것 / 오늘 만들지 않을 것 (명확히 구분)
5. 발표에서 보여줄 "도파민 포인트" — AI가 눈앞에서 뭔가를 대신 해주는 순간을 한 줄로
```

> [!IMPORTANT]
> **"오늘 만들지 않을 것"을 반드시 문서에 남기세요.**
> 화면 개수나 기능 범위를 미리 정해두지 않는 대신, 이 목록이 그 역할을 합니다.
> 구현하다 자꾸 기능을 붙이고 싶어질 때 이걸 보고 참으세요. 앞서 나온 **PRD 확정 후 변경 금지**와 세트입니다.

### `CLAUDE.md` 작성

무엇을 만들든 상관없이, PRD를 근거로 짧은 지침 하나만 만들어두면 AI가 훨씬 안정적으로 움직입니다.

**[Claude Code 프롬프트]**
```text
PRD.md를 읽고 이 프로젝트용 CLAUDE.md를 만들어줘.

- 기술 스택은 우리가 오늘 쓰기로 한 것으로 적어줘
  (Day 2와 같은 웹 스택이면: Next.js App Router, TypeScript, Tailwind, Supabase)
  (자동화 스크립트나 다른 형태라면 그에 맞는 언어/도구로)
- 작업을 마칠 때마다 실행할 검증 명령을 정해줘 (예: 웹이면 lint/타입체크, 스크립트면 실제로 한 번 돌려보기)
- any 타입 금지 (해당되는 언어라면)
- 결과가 이상하게 나오면 코드보다 권한/설정(API 키, 인증 등)을 먼저 의심할 것
```
